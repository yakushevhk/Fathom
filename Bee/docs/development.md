# Development

## Setup

```bash
cd Bee
npm install        # Node ≥ 22.12 required (repo CI pins 24)
npm run dev        # http://localhost:3000 — creates+seeds data/bee.db
```

Scripts: `dev`, `build`, `start`, `lint` (`eslint` flat config),
`typecheck` (`tsc --noEmit`).

### Dev-server quirk (Linux)

`next dev` exits on **stdin EOF** — a detached/one-shot shell kills it on
exit. Keep it in a persistent TTY (`tty: true` shell, tmux, or a terminal
tab). This is the most common "the server won't stay up" cause.

### Reseeding

`getDb()` seeds only when `members` is empty. To get a clean workspace:

```bash
rm -f data/bee.db data/bee.db-*   # WAL/SHM siblings
# restart dev server
```

## Repo-specific conventions

- **Next 16 async params**: `params`/`searchParams` are `Promise`s —
  `await ctx.params` in every route handler (see `src/app/api/*/route.ts`)
  and `await params` / `use()` in pages. This is enforced by
  `Bee/AGENTS.md` (auto-generated by `next dev` — commit it, don't revert).
- **Tailwind v4**: no config file — `@import "tailwindcss"` +
  `@theme inline` in `globals.css` only.
- **eslint flat config** (`eslint.config.mjs`) uses eslint-config-next's
  native flat exports (`core-web-vitals`, `typescript`). Notable rule:
  `react-hooks/set-state-in-effect` **forbids setState inside effects** —
  use render-phase adjustment (`const [prev, setPrev] = useState(x); if
  (prev !== x) { setPrev(x); … }`) or `useSyncExternalStore`.
- **Client state**: `useHive()` only — don't add per-component SSE or
  fetch-into-state for log data; merge `liveEvents` by `id` (see
  realtime.md).
- **Security**: keep `next.config.ts` headers mirrored with `apps/web`;
  never render user text outside `Markdown.tsx`.
- **Icons/colors**: `lucide-react` + tokens only (design-system.md).

## CI

`.github/workflows/ci.yml` runs `npm ci && npm run lint && npm run build`
for `Bee/` on Node 24 (the "Build Bee Workspace" step). Match locally with
the same trio before pushing — `tsc` is stricter than `next build`'s
bundled checks.

## Testing checklist

There's no unit suite — verification is a scripted browser walk-through
against the seeded log (the `.agents/skills/testing-bee-hive` skill
captures the full procedure). Core matrix:

| Area | Check |
| --- | --- |
| Rooms | markdown render, day separators, dense grouping, send→reply flow, typing indicator |
| Live merge | rapid back-to-back `POST …/messages` (coalescing) → **all** appear without reload |
| Approvals | `/review` approve+reject, in-room card decide, decided state persists after F5 |
| Workflows | ticker advances a run; step timeline + in-room completion event |
| Pulse/Search | kind filters, live prepend order, `⌘K` navigation |
| Rooms/DM | create (incl. 409), announcement 403, DM peer replies |
| Edge | XSS payload escaped, 400/413 guards, triple-Enter sends once, theme persists |
