# Enterprise Server Extension (`enterprise/server/`)

This directory contains the source-available enterprise extension layer for the backend server. It implements offline cryptographic license verification, multi-tenant fleet policies, and enterprise feature gates.

---

## Architectural Role & Dynamic Loading

The enterprise layer is designed as a decoupled plug-in that never tightly couples to the open-source core:

```
+-------------------------------------------------------------+
|               server/enterprise.ts (OSS Core)               |
|  - Dynamically probes ../enterprise/server/index.{ts,js}    |
|  - Reads OMB_LICENSE_KEY from environment                   |
|  - Calls register({ licenseKey })                           |
|  - Exposes /api/edition endpoint                            |
+-------------------------------------------------------------+
                              |
                     (Dynamic Import)
                              v
+-------------------------------------------------------------+
|                 enterprise/server/index.ts                  |
|  - Verifies Ed25519 cryptographic signature                 |
|  - Unpacks Zod claims: customer, features, expiry           |
|  - Returns RegisteredLayer status                           |
+-------------------------------------------------------------+
```

### Clean OSS Fallback
1. If this directory is deleted or omitted from a build, `server/enterprise.ts` gracefully degrades to the open-source edition (`edition: "oss"`) without compilation errors or missing dependency crashes.
2. If an invalid or expired `OMB_LICENSE_KEY` is provided, core startup does not halt; it reports open-source mode and provides an operator notice detailing the license issue.
3. No telemetry or "phone-home" network calls are made. Verification is entirely offline.

## Key Modules & Exported Contracts

### 1. Enterprise Layer Registration (`index.ts`)
The neutral entrypoint invoked by `server/enterprise.ts`:
- **`RegisteredLayer`**:
  ```ts
  export interface RegisteredLayer {
    customer: string;
    features: string[];
    expiresAt: string | null;
  }
  ```
- **`register(options: { licenseKey: string | undefined })`**: Validates the license and returns the customer entitlements. Returns `null` if no key is configured.

### 2. Cryptographic Licensing Engine (`license.ts`)
Implements an Ed25519 digital signature scheme over base64url JSON claims:
- **Format**: `omb1.<claims>.<signature>`
  - `omb1`: Protocol version identifier.
  - `<claims>`: Base64url-encoded JSON payload validated against `claimsSchema`.
  - `<signature>`: Base64url-encoded raw Ed25519 signature generated by the private signing authority.
- **Claims Schema (`claimsSchema`)**:
  ```ts
  {
    v: 1,
    customer: string,      // Customer or organization name
    features: string[],    // Entitlement IDs (e.g. "whitelabel", "sso", "fleet", "audit")
    issued: string,        // YYYY-MM-DD
    expires: string | null // YYYY-MM-DD or null for perpetual
  }
  ```
- **Key Rotation (`LICENSE_PUBLIC_KEYS`)**: Array of trusted Ed25519 public JWK keys. Keys are rotated by appending new public keys to the array; existing valid keys signed with older historical keys remain supported.
- **`verifyLicenseKey(key, options)`**:
  - Validates formatting and header prefix.
  - Verifies Ed25519 signature against all trusted public keys.
  - Parses JSON claims and validates schema conformance.
  - Asserts that current system time has not passed `expires` (for non-perpetual licenses).
- **`issueLicenseKey(claims, privateJwk)`**:
  - Internal utility used by license issuance tooling (`scripts/issue-license.mjs`) and unit tests.

## Security & Verification Invariants

1. **Strict Offline Verification**: The server performs no external license checks. Verification relies purely on asymmetric public-key cryptography.
2. **Private Key Isolation**: Private keys are strictly excluded from the codebase and build artifacts; only the public JWK coordinate (`x`) is checked into source.
3. **Fail-Closed Entitlements**: Unknown or malformed claims prevent feature unlocking; unknown feature strings are carried safely without throwing, but missing required claims reject the license.
4. **Time Tamper Resistance**: Expired licenses produce human-actionable error messages while preventing enterprise feature activation.

## Testing & Verification

Run the dedicated license verification test suite:
```sh
pnpm test enterprise/server/license.test.ts
```
The tests assert:
- Successful verification of validly signed perpetual and term licenses.
- Rejection of tampered claims or corrupted signatures.
- Expiration enforcement against historical and future timestamps.
- Key rotation compatibility across multiple public keys.
