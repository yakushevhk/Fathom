  <section id="verification-tools">
    <h2 data-i18n="docsOutreach.verifyToolsTitle">Verification Tools Deep Dive</h2>
    <p data-i18n="docsOutreach.verifyToolsSub">
      Raw data is noisy. Verification tools clean, normalize, and score every contact record before it
      enters your pipeline. Here is exactly what each tool does and how to interpret its output.
    </p>

    <div class="tool-card" id="verify-email">
      <div class="tool-card-header">
        <div class="tool-card-icon">✉️</div>
        <div>
          <h3 class="tool-card-name">verify_email</h3>
          <span class="tool-card-tag">5-Stage Pipeline</span>
        </div>
      </div>
      <p>
        The most critical verification tool. Every email passes through five sequential stages — each
        stage can short-circuit the pipeline if a hard failure is detected (e.g., invalid syntax). The
        final confidence score is a composite of all stage results.
      </p>
      <h4>The 5-stage pipeline in detail</h4>
      <table class="mini-table">
        <thead><tr><th>Stage</th><th>What happens</th><th>Score impact</th></tr></thead>
        <tbody>
          <tr>
            <td><strong>1. Syntax</strong></td>
            <td>
              Validates against RFC 5322 subset: exactly one <code>@</code>, total length &le;254,
              local part &le;64, no leading/double dots, TLD is non-numeric and at least 2 chars.
            </td>
            <td>Fail → 0.0 (hard stop)</td>
          </tr>
          <tr>
            <td><strong>2. MX lookup</strong></td>
            <td>
              DNS-over-HTTPS via Google (primary) and Cloudflare (fallback). If no MX records exist,
              falls back to A-record lookup per RFC 5321 &sect;5.1.
            </td>
            <td>Resolved → +0.4; NXDOMAIN → 0.1 (hard stop)</td>
          </tr>
          <tr>
            <td><strong>3. Disposable</strong></td>
            <td>
              Checks the domain against ~50 known throwaway providers: mailinator, yopmail,
              guerrillamail, tempmail, 10minutemail, etc.
            </td>
            <td>Match → &minus;0.3</td>
          </tr>
          <tr>
            <td><strong>4. Role-based</strong></td>
            <td>
              Flags departmental / noreply addresses: <code>info@</code>, <code>sales@</code>,
              <code>support@</code>, <code>admin@</code>, <code>no-reply@</code>, <code>billing@</code>, etc.
            </td>
            <td>Match → &minus;0.15 (still usable, but lower priority)</td>
          </tr>
          <tr>
            <td><strong>5. SMTP probe</strong></td>
            <td>
              Optional (<code>smtp_check=true</code>). Opens TCP:25, sends <code>HELO</code>,
              <code>MAIL FROM</code>, <code>RCPT TO</code>. Accepts 250/251 as deliverable, 5xx as
              rejected. <strong>Never sends DATA</strong> — no actual email is delivered.
            </td>
            <td>Accepted → &ge;0.95; Rejected → &le;0.2; Timeout → capped at 0.9</td>
          </tr>
        </tbody>
      </table>

      <h4>Confidence scoring algorithm</h4>
      <div class="code-block">
        <div class="code-header"><span class="code-lang">python</span></div>
        <pre><code dangerouslySetInnerHTML={{__html: `{\`score = 0.5                                    # base
if mx_resolved:     score += 0.4               # domain is real
if disposable:      score -= 0.3               # throwaway domain
if role_based:      score -= 0.15              # department mailbox
if smtp_accepted:   score = max(score, 0.95)   # server confirmed
if smtp_rejected:   score = min(score, 0.2)    # server denied
if no_smtp_check:   score = min(score, 0.9)    # can't fully confirm

    <h3 id="contacts-db">How contacts.db works</h3>
    <p>
      All contacts are stored in <code>contacts.db</code>, a SQLite database in your project's data
      directory. The schema is designed for fast dedup and flexible metadata.
    </p>
    <div class="code-block">
      <div class="code-header"><span class="code-lang">sql</span></div>
      <pre><code dangerouslySetInnerHTML={{__html: `{\`CREATE TABLE contacts (
    id          TEXT PRIMARY KEY,   -- UUID v4
    name        TEXT,
    email       TEXT,
    phone       TEXT,
    title       TEXT,
    company     TEXT,
    linkedin    TEXT,
    twitter     TEXT,
    github      TEXT,
    website     TEXT,
    location    TEXT,
    bio         TEXT,
    confidence  REAL DEFAULT 0.0,
    source_url  TEXT,
    crm_id      TEXT,               -- set after CRM push
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP

    ON contacts(email, phone, linkedin);\`}`}} /></pre>

    <ul class="check-list">

      <li><strong>Merge strategy:</strong> non-empty fields from the newer record overwrite older empty fields; confidence takes the higher value.</li>
      <li><strong>Name normalization:</strong> diacritics stripped, whitespace collapsed, case-insensitive comparison.</li>
    </ul>

  {/* ============ WATCH MODE & MONITORING ============ */}
  <section id="watch-mode">
    <h2 data-i18n="docsOutreach.watchTitle">Watch Mode &amp; Monitoring</h2>
    <p data-i18n="docsOutreach.watchSub">
      Watch mode transforms a one-shot outreach task into a recurring monitor. Re-run the same query
      on a schedule, diff the results, and get notified only when new contacts appear.
    </p>

    <h3 id="repeat-flag">The --repeat flag</h3>
    <p>
      Add <code>--repeat N</code> to re-run every <code>N</code> seconds. The agent runs the full
      pipeline on each cycle — but only saves contacts that are new or changed since the last run.
    </p>
    <div class="code-block">
      <div class="code-header"><span class="code-lang">bash</span></div>
      <pre><code dangerouslySetInnerHTML={{__html: `{\`# Re-run every 24 hours (86400 seconds)
fathom run "Find new VP Engineering hires at Series B startups in SF" \\\\
  --repeat 86400\`}`}} /></pre>
    </div>

    <h3 id="diff-detection">How diff detection works</h3>
    <ul class="check-list">
      <li>Each run snapshots the contact database state (hash of email + phone + LinkedIn).</li>
      <li>Before saving, new records are compared against the previous snapshot.</li>
      <li>Only genuinely new or updated contacts trigger notifications.</li>
      <li>Removed contacts (present in snapshot, absent in new run) are logged but not deleted.</li>
    </ul>

    <h3 id="notification-channels">Notification channels</h3>
    <div class="steps">
      <div class="step">
        <h3>Webhook</h3>
        <p>
