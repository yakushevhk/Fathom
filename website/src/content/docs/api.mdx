        <h1 class="api-title" data-i18n="docsApi.title">HTTP API Reference</h1>
        <p class="api-description" data-i18n="docsApi.desc">
          Full reference for the Fathom REST API. Manage autonomous worker sessions, stream events, and operate coworkers, schedules, memory, governance and computer use programmatically.
        </p>
      </div>

      {/* OVERVIEW */}
      <section id="overview" class="api-section">
        <h2 class="api-section-title" data-i18n="docsApi.overviewTitle">Overview</h2>
        <p class="api-text" data-i18n="docsApi.overviewText">
          The Fathom API is a RESTful control plane for universal autonomous workers. It manages sessions, persistent coworkers, scheduled operations, memory, governance, computer use and notifications; research is one supported workflow. All responses are JSON-encoded. Streaming endpoints use Server-Sent Events (SSE).
        </p>
        <div class="info-block">
          <div class="info-label" data-i18n="docsApi.baseUrlLabel">Base URL</div>
          <code class="info-code">http://localhost:8080</code>
        </div>
        <p class="api-text" data-i18n="docsApi.overviewAuthText">
          The API supports two authentication methods via HTTP headers:
        </p>
        <div class="code-block">
          <div class="code-header">
            <span class="code-lang">HTTP Headers</span>
          </div>
          <pre><code set:html={`Authorization: Bearer &lt;your-api-key&gt;
X-Api-Key: &lt;your-api-key&gt;`} /></pre>
        </div>
      </section>

      {/* AUTHENTICATION */}
      <section id="authentication" class="api-section">
        <h2 class="api-section-title" data-i18n="docsApi.authTitle">Authentication</h2>
        <p class="api-text" data-i18n-html="docsApi.authText">
          When <code>FATHOM_API_KEYS</code> is configured, API requests under <code>/api/v1</code> require a matching Bearer token or <code>X-Api-Key</code> header. With no keys configured, loopback deployments allow open access; binding the server to a non-loopback address requires configuring keys.
        </p>
        <div class="code-block">
          <div class="code-header">
            <span class="code-lang">Environment</span>
          </div>
          <pre><code set:html={`FATHOM_API_KEYS=key-abc123,key-def456,key-ghi789`} /></pre>
        </div>
        <p class="api-text" data-i18n-html="docsApi.authRateLimit">
          Each key maps to an independent identity. Rate limiting is applied per-key: <strong>120 requests/minute</strong> for standard endpoints. Exceeding limits returns <code>429 Too Many Requests</code>.
        </p>
        <div class="callout callout-warn">
          <div class="callout-icon">⚠</div>
          <div data-i18n-html="docsApi.authWarn">
            <strong>Security note:</strong> Never expose API keys in client-side code or public repositories. Use environment variables or a secrets manager.
          </div>
        </div>
      </section>
