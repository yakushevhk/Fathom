## RPC mode

Start the coding agent as a bounded NDJSON service:

```bash
parallel --mode rpc
```

Stdout contains protocol frames only; logs go to stderr. The first event is a
`ready` frame. Requests carry the active `session_id` and are correlated by
`id`:

```json
{"protocol_version":"1.0","id":"1","session_id":"...","method":"prompt","params":{"text":"Inspect this repository"}}
{"protocol_version":"1.0","id":"2","session_id":"...","method":"get_state","params":{}}
{"protocol_version":"1.0","id":"3","session_id":"...","method":"abort","params":{"reason":"user_cancelled"}}
```

Supported commands:

| Command | Purpose |
| --- | --- |
| `prompt` | Start an agent turn |
| `steer` | Inject an instruction into the active session |
| `follow_up` | Queue another turn |
| `abort` | Cancel the active turn |
| `get_state` | Read session/model status |
| `get_messages_page` | Read bounded paginated history |
| `get_subagents` | Read child-agent state |
| `compact` | Compact context manually |
| `set_model` | Select the active model |

Events are typed: agent lifecycle, tool lifecycle, permission requests,
questions, subagents, advisor observations, compaction, and errors. Clients
must process events independently from responses. Frames are bounded by the
protocol implementation; oversized input must be rejected.

## GPUI client

The native GUI is in `research-agent/gui`. It launches and owns the RPC child,
streams structured events, and sends real control messages:

```bash
cd research-agent
cargo run -p parallel-gui
```

The Research view supports live output, tool events, steering, cancellation,
approval/denial dialogs, and question answers. Contacts, sessions, jobs,
memory, profiles, skills, and MCP data remain available in the surrounding
screens.

## ACP

The minimal Agent Client Protocol adapter supports initialization, session
creation, prompt, cancellation, streamed updates, and permission requests:

```bash
cargo run -p parallel-acp
```

Unsupported methods return JSON-RPC errors and unsupported capabilities are not
advertised.

## HTTP collaboration

`parallel serve` exposes authenticated REST, SSE, WebSocket, and collaboration
routes. Issue a session-bound signed token through
`POST /api/collaboration/token`, then connect to `GET /api/collaboration`.
View-only clients can receive history/live events but cannot prompt or stop the
host session.
