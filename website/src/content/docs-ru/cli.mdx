  <section id="run">
    <h2>run</h2>
    <p>Автономная работа без интерфейса. Координатор разбивает задачу на субагентов, синтезирует их результаты и пишет структурированный вывод. Задача передаётся позиционным аргументом <code>[QUERY]</code> или читается из файла через <code>--task-file</code>. С <code>--repeat</code> становится режимом наблюдения: каждый запуск сравнивается с предыдущим и настроенные уведомления могут сообщать об изменениях.</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Флаг</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>-o, --output &lt;DIR&gt;</td><td>Выходная директория для результатов (по умолчанию: из конфига)</td></tr>
          <tr><td>--repeat &lt;SECS&gt;</td><td>Режим наблюдения — повторять каждые N секунд, сравнивать запуски, оповещать о новых контактах</td></tr>
          <tr><td>--profile &lt;NAME&gt;</td><td>Персона: hunter | analyst | validator | файл в ~/.fathom/profiles/ | путь к .toml</td></tr>
          <tr><td>--task-file &lt;FILE&gt;</td><td>Читать задачу из файла вместо позиционного аргумента</td></tr>
        </tbody>
      </table>
    </div>
    <div class="code-card">
      <pre><code set:html={`fathom run "Compare Rust and Go for backend services" --output ./research/

# режим наблюдения: пересбор каждые 6 часов, оповещение о новых контактах
fathom run "Acme leadership team" --repeat 21600

# с персоной
fathom run --profile hunter "Find the CTO of Acme"`} /></pre>
    </div>
  </section>

  <section id="tui">
    <h2>tui</h2>
    <p>Интерактивный терминальный интерфейс (ratatui): живое дерево агентов, стриминг вывода, журнал событий, панели задач и памяти, процесс подтверждения. Клавиши и панели — в разделе <a href="#tui-interface">Интерфейс TUI</a>.</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Флаг</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>[QUERY]</td><td>Опциональный начальный запрос</td></tr>
          <tr><td>--profile &lt;NAME&gt;</td><td>Персона, применяемая к сессиям, запущенным из TUI</td></tr>
          <tr><td>--replay &lt;SESSION-ID&gt;</td><td>Воспроизвести сохранённую сессию вместо живого запуска (принимается префиксное совпадение)</td></tr>
        </tbody>
      </table>
    </div>
    <div class="code-card">
      <pre><code set:html={`fathom tui
fathom tui "Find VPs of Engineering at fintech startups" --profile analyst
fathom tui --replay 3f9c2a   # просмотр сохранённой сессии`} /></pre>
    </div>
  </section>

  <section id="serve">
    <h2>serve</h2>
    <p>HTTP-сервер на Axum: управление сессиями и задачами, потоки событий SSE, API памяти, метрики Prometheus и веб-дашборд на <code>/dashboard</code>. По умолчанию слушает на loopback.</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Флаг</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>--port &lt;PORT&gt;</td><td>Порт прослушивания (по умолчанию: 8080)</td></tr>
          <tr><td>--host &lt;HOST&gt;</td><td>Адрес привязки (по умолчанию: 127.0.0.1)</td></tr>
        </tbody>
      </table>
    </div>
    <div class="callout">Привязка не-loopback адреса (<code>--host 0.0.0.0</code>) требует установки <code>FATHOM_API_KEYS</code> — иначе запуск отклоняется. Ключи передаются через <code>Authorization: Bearer</code> или <code>X-Api-Key</code>. Лимит запросов на клиента настраивается через <code>FATHOM_RATE_LIMIT</code>.</div>
    <div class="code-card">
      <pre><code set:html={`fathom serve --port 8080
fathom serve --host 0.0.0.0   # требует FATHOM_API_KEYS`} /></pre>
    </div>
  </section>

  <section id="mcp-serve">
    <h2>mcp-serve</h2>
    <p>Экспонирует все инструменты агента внешним MCP-клиентам (Claude, ZCode, …) через stdio. Вызовы инструментов выполняются через тот же реестр, который используют агенты. Логирование идёт в stderr, чтобы stdout оставался чистым JSON-RPC.</p>
    <div class="code-card">
      <pre><code set:html={`fathom mcp-serve`} /></pre>
    </div>
    <p>Добавьте в конфигурацию вашего MCP-клиента:</p>
    <div class="code-card">
      <pre><code set:html={`{ "command": "fathom", "args": ["mcp-serve"] }`} /></pre>
    </div>
  </section>

  <section id="memory">
    <h2>memory</h2>
    <p>Обслуживание долговременной семантической базы знаний без запуска агента: гибридный поиск (векторы + BM25), append-only цепочки версий, дистилляция и GC. Ничего никогда не удаляется молча.</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Подкоманда</th><th>Флаги</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>search &lt;query&gt;</td><td>--top-k (по умолчанию 10), --scope agent|user|run|all</td><td>Гибридный семантический + ключевой поиск</td></tr>
          <tr><td>list</td><td>--scope, --status active|superseded|archived|all, -n</td><td>Список сохранённых фактов, новые первыми</td></tr>
          <tr><td>get &lt;id&gt;</td><td>--follow active|latest|full_history</td><td>Одна запись плюс её цепочка версий</td></tr>
          <tr><td>stats</td><td>—</td><td>Счётчики по области/статусу, граф сущностей, размер БД</td></tr>
          <tr><td>rebuild</td><td>—</td><td>Пересчитать эмбеддинги всех фактов текущей моделью</td></tr>
          <tr><td>distill</td><td>--session &lt;key&gt;, --dry-run</td><td>Дистиллировать факты сессии области run в долговечные знания</td></tr>
          <tr><td>gc</td><td>--ttl-days &lt;N&gt;, --dry-run</td><td>Архивировать устаревшие run-факты, компактировать раздутые группы областей</td></tr>
          <tr><td>nuke</td><td>--scope, --yes</td><td>Жёстко удалить записи области; требует явного --yes</td></tr>
        </tbody>
      </table>
    </div>
    <div class="code-card">
      <pre><code set:html={`fathom memory search "email of the director of Acme" --top-k 10
fathom memory list --scope agent --status active -n 20
fathom memory get 7f31 --follow full_history
fathom memory stats
fathom memory distill --dry-run
fathom memory gc --ttl-days 30 --dry-run`} /></pre>
    </div>
  </section>

  <section id="profiles">
    <h2>profiles</h2>
    <p>Персоны для <code>run --profile</code> и <code>tui --profile</code>: готовый системный промпт плюс опциональные переопределения модели, температуры, глубины, числа агентов и запрещённых инструментов. Встроенные: <code>hunter</code>, <code>analyst</code>, <code>validator</code>; свои TOML-файлы лежат в <code>~/.fathom/profiles/</code>.</p>
    <div class="code-card">
      <pre><code set:html={`fathom profiles list
fathom profiles show hunter
fathom profiles new my-persona   # создаёт файл-шаблон`} /></pre>
    </div>
  </section>

  <section id="contacts">
    <h2>contacts</h2>
    <p>База OSINT-контактов, собранная через <code>save_contacts</code>: список, экспорт, дедупликация и отправка в настроенную CRM (amoCRM, Bitrix24, HubSpot).</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Подкоманда</th><th>Флаги</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>list</td><td>--limit (по умолчанию 50)</td><td>Список сохранённых контактов</td></tr>
          <tr><td>export</td><td>--format csv|vcf|json|xlsx (по умолчанию csv), -o, --output &lt;DIR&gt;</td><td>Экспорт контактов в файл</td></tr>
          <tr><td>dedup</td><td>--merge</td><td>Найти дубликаты (нормализованный email/телефон); --merge сворачивает каждую группу в самую полную строку</td></tr>
          <tr><td>push-crm</td><td>—</td><td>Отправить все сохранённые контакты в настроенную CRM</td></tr>
        </tbody>
      </table>
    </div>
    <div class="code-card">
      <pre><code set:html={`fathom contacts list

fathom contacts push-crm`} /></pre>
    </div>
  </section>

  <section id="jobs">
    <h2>jobs</h2>
    <p>Долговечные фоновые задачи в SQLite: попытки с самовосстанавливающимися повторами (задача переподчиняется с добавлением предыдущей ошибки), переживают перезапуски.</p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Подкоманда</th><th>Флаги</th><th>Описание</th></tr></thead>
        <tbody>
          <tr><td>submit &lt;task&gt;</td><td>--attempts (по умолчанию 3)</td><td>Запустить задачу отсоединённой в фоне</td></tr>
          <tr><td>list</td><td>—</td><td>Список всех задач</td></tr>
          <tr><td>status &lt;id&gt;</td><td>--watch &lt;SECS&gt;</td><td>Детальный статус; --watch обновляет до терминального состояния</td></tr>
          <tr><td>logs &lt;id&gt;</td><td>-n &lt;LINES&gt; (по умолчанию 50)</td><td>stdout + stderr всех попыток</td></tr>
          <tr><td>cancel &lt;id&gt;</td><td>—</td><td>Отменить задачу в очереди или выполняющуюся</td></tr>
          <tr><td>rerun &lt;id&gt;</td><td>—</td><td>Перезапустить завершённую/отменённую/протухшую задачу с нуля</td></tr>

    </div>

  <section id="tui-interface">
    <h2>Интерфейс TUI</h2>
    <p>Заголовок показывает ID сессии, прошедшее время и спарклайн расхода токенов за сессию. В режиме повтора заголовок помечается <code>[REPLAY]</code>, и сохранённое дерево агентов загружается с финальными статусами.</p>

    <h3 id="tui-keys">Клавиши</h3>
    <div class="mini-table-wrap">

        <thead><tr><th>Клавиша</th><th>Действие</th></tr></thead>

  <section id="tui-deep-dive">
    <h2>TUI подробно</h2>
    <p>
      TUI (терминальный пользовательский интерфейс) построен на <code>ratatui</code> и даёт представление
      о рое агентов в реальном времени. Подробный взгляд на каждую панель и функцию.
    </p>

    <h3>Детали панелей</h3>
    <div class="ops-grid">
      <div class="ops-card">
        <div class="ops-name">Agents</div>
        <p>Живое дерево агентов с координатором в корне и субагентами-детьми. Каждый агент показывает статус (running, complete, failed), текущий вызов инструмента и прошедшее время. Up/Down перемещают курсор, Left/Right сворачивают/разворачивают поддеревья. Детали выбранного агента появляются в панели Output.</p>
      </div>
      <div class="ops-card">
        <div class="ops-name">Output</div>
        <p>Финальный собранный вывод, стримится токен за токеном по мере работы автора. В режиме повтора показывает полный сохранённый вывод. Когда несколько авторов работают параллельно, их выводы чередуются с маркерами agent-id.</p>
      </div>
      <div class="ops-card">
        <div class="ops-name">Log</div>
        <p>Журнал событий: запуски агентов с описаниями задач, вызовы инструментов со сводками аргументов и временем выполнения в миллисекундах, предупреждения (события компактификации, усечения) и находки по мере обнаружения. Каждая запись помечена временем относительно начала сессии.</p>
      </div>
      <div class="ops-card">
        <div class="ops-name">Tools</div>
        <p>Активные и недавние вызовы инструментов с их аргументами, статусом выполнения и таймингом. Показывает, какие инструменты работают параллельно, а какие сериализованы. Ожидающие подтверждения вызовы подсвечены — нажмите <code>y</code> или <code>n</code> для действия.</p>
      </div>
      <div class="ops-card">
        <div class="ops-name">Jobs</div>
        <p>Долговечные фоновые задачи, отправленные через <code>jobs submit</code>. Показывает состояние задачи (queued, running, complete, failed), число попыток и последнюю ошибку, если есть. Обновляется автоматически.</p>
      </div>
      <div class="ops-card">
        <div class="ops-name">Memory</div>
        <p>Недавние записи из хранилища семантической памяти. Показывает новые факты по мере их поглощения во время запуска. Полезно для проверки, что агент запоминает правильные вещи.</p>
      </div>
    </div>

    <h3>Спарклайн заголовка</h3>
    <p>
      Строка заголовка показывает три вещи: ID сессии (первые 8 символов), прошедшее время (формат MM:SS)
      и спарклайн-график расхода токенов. Спарклайн — скользящее окно в 60 секунд, показывающее, сколько
      токенов потреблялось в секунду. Плоский спарклайн означает, что агент ждёт (заблокирован на инструменте
      или простаивает); растущий спарклайн — активная генерация; всплеск указывает на обработку большого
      вывода инструмента.
    </p>

    <h3>Браузер сессий (клавиша 'b')</h3>
    <p>
      Нажмите <code>b</code>, чтобы открыть браузер сессий — список всех прошлых сессий, хранящихся в
      базе. Навигация через Up/Down, Enter загружает сессию в режиме повтора. Это эквивалентно
      <code>tui --replay &lt;id&gt;</code>, но доступно изнутри TUI. Сессии отсортированы новыми
      первыми и показывают: ID, запрос (усечённый), статус и метку времени.
    </p>

    <h3>Режим ссылки на файл (клавиша '@')</h3>
    <p>
      В режиме вставки введите <code>@</code> и путь, чтобы сослаться на локальный файл. Содержимое файла
      читается и включается как контекст для агента. Полезно для:
    </p>
    <div class="check-list">
      <div class="check-item"><span class="check-mark">✓</span><span>Передачи CSV контактов для валидации: <code>@./contacts.csv validate these contacts</code></span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Подачи файла задачи: <code>@./task.txt</code> читает файл как запрос</span></div>

    </div>

  <section id="tips">
    <h2>Советы и хитрости CLI</h2>

    <h3>Используйте --task-file для сложных запросов</h3>
    <p>
      Для длинных или структурированных запросов записывайте их в файл вместо передачи позиционным аргументом.
      Это избегает проблем экранирования шелла и позволяет версионировать ваши исследовательские промпты.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">файл задачи</span></div>
      <pre><code set:html={`# task.txt
Research the competitive landscape of AI coding assistants.
Include:
1. GitHub Copilot, Cursor, Codeium, Tabnine, Cody
2. Pricing models and enterprise features
3. Technical architecture (local vs cloud, model choices)
4. Market share estimates and growth trajectories
5. Key differentiators and weaknesses

Format as a comparison table with a recommendation section.

# Запуск с файлом задачи
fathom run --task-file task.txt -o ./ai-coding-tools/`} /></pre>
    </div>

    <h3>Используйте --repeat для циклов мониторинга</h3>
    <p>
      Флаг <code>--repeat</code> превращает <code>run</code> в режим наблюдения. Каждый цикл перезапускает
      запрос, сравнивает результаты с предыдущим запуском и оповещает о новых контактах или изменённых находках.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">мониторинг</span></div>
      <pre><code set:html={`# Проверка новых сигналов по Acme Corp каждые 6 часов
fathom run "Acme Corp latest news and hiring" --repeat 21600

# Мониторинг доски вакансий каждый час
fathom run "New postings on careers.acme.com" --repeat 3600`} /></pre>
    </div>

    <h3>Используйте --profile для поведения под кампанию</h3>
    <p>
      Комбинируйте профили с одним запросом для разных перспектив. Запустите один раз с <code>hunter</code>
      для контактов, затем с <code>analyst</code> для глубокого исследования тех же компаний.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">двойной проход</span></div>
      <pre><code set:html={`# Проход 1: сбор контактов
fathom run --profile hunter "Series B fintech companies" -o ./fintech/

# Проход 2: глубокий анализ той же темы
fathom run --profile analyst "Series B fintech companies" -o ./fintech-analysis/`} /></pre>
    </div>

    <h3>Передавайте вывод другим инструментам</h3>
    <p>
      CLI пишет структурированный Markdown и JSON, которые можно передавать другим инструментам для дальнейшей обработки.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">пайпы</span></div>
      <pre><code set:html={`# Экспорт контактов и фильтрация через jq
fathom contacts export --format json | jq '.[] | select(.title | contains("CTO"))'

# Поиск в памяти и форматирование как markdown-ссылок
fathom memory search "fintech" --top-k 5 | grep -oP 'https?://\\\\S+' | sort -u

# Запуск статистики и сохранение в файл
fathom stats -o ./results/ > stats-report.md`} /></pre>
    </div>

    <h3>Находите прошлые исследования через sessions</h3>
    <p>
      Команда <code>sessions</code> — ваша история исследований. Используйте поиск по подстроке для нахождения
      прошлых запусков по теме, компании или дате.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">сессии</span></div>
      <pre><code set:html={`# Найти все сессии про fintech
fathom sessions list --search "fintech"

# Показать последние 5 сессий
fathom sessions list -n 5

# Просмотр деталей конкретной сессии (префиксное совпадение)
fathom sessions show 3f9c2a`} /></pre>
    </div>

    <h3>Анализируйте производительность инструментов через stats</h3>
    <p>
      Команда <code>stats</code> показывает статистику вызовов по инструментам из записанной сессии: числа вызовов,
      задержки p50/p95 и частоты ошибок. Используйте для нахождения медленных инструментов или оптимизации вашего пайплайна исследования.
    </p>
