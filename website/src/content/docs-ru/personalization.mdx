    <h2>Встроенные профили подробно</h2>

    <h3>hunter</h3>
    <p>
      Профиль <strong>hunter</strong> оптимизирован для сбора контактов максимальным объёмом. Он принудительно ставит
      <code>max_agents = 6</code>, держит temperature на 0.4 для стабильного извлечения и всегда включает
      <code>extract_contacts</code>, <code>save_contacts</code> и <code>verification</code> в цепочку инструментов.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">hunter.toml</span></div>
      <pre><code set:html={`[profile]
name = "hunter"
description = "Harvest maximum verified contacts fast"
prompt = """
You are a contact-harvesting agent. Your sole objective is to find and
verify as many contacts as possible. Prioritize volume but never save
unverified contacts. Always run email syntax + MX checks before saving.
For each company, search for C-suite, VP Engineering, and Head of Product.
"""
temperature = 0.4
max_agents = 6
max_depth = 2
deny_tools = ["git_push"]`} /></pre>
    </div>
    <div class="code-card code-card--gap">
      <div class="code-header"><span class="code-lang">пример</span></div>
      <pre><code set:html={`fathom run --profile hunter "Find engineering leaders at YC W24 companies"`} /></pre>
    </div>
    <p>
      Что меняется: агент запускает до 6 параллельных субагентов, каждый обрабатывает свой срез поискового
      пространства. Системный промпт настроен на широту — проверить каждую компанию, извлечь каждый видимый
      контакт, верифицировать email и телефон, сохранить сразу. Запрет <code>git_push</code> предотвращает
      случайные коммиты, если папка исследования — git-репозиторий.
    </p>

    <h3>analyst</h3>
    <p>
      Профиль <strong>analyst</strong> — read-only глубокий исследователь. Он запрещает <code>save_contacts</code>
      и <code>git_push</code>, поэтому побочных эффектов нет. Temperature 0.3 для точного вывода с цитатами.
      Лучше всего подходит для конкурентного анализа, технических глубоких погружений и due diligence.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">analyst.toml</span></div>
      <pre><code set:html={`[profile]
name = "analyst"
description = "Deep, cited, read-only research"
prompt = """
You are a research analyst. Produce thoroughly sourced findings with
inline citations. Every claim MUST link to a source URL. Cross-reference
facts across multiple sources. Flag conflicting information explicitly.
Never save contacts or modify external systems — you are read-only.
"""
model = "gpt-4o"
temperature = 0.3
max_agents = 4
max_depth = 3
max_iterations = 30
deny_tools = ["save_contacts", "git_push"]`} /></pre>
    </div>
    <div class="code-card code-card--gap">
      <div class="code-header"><span class="code-lang">пример</span></div>
      <pre><code set:html={`fathom run --profile analyst "Evaluate the competitive landscape of vector databases"`} /></pre>
    </div>
    <p>
      Что меняется: агент использует <code>max_iterations = 30</code> для более длинных цепочек исследования и
      <code>max_depth = 3</code> для более глубокой вложенности субагентов. Промпт требует цитировать каждое
      утверждение и явно помечать противоречия.
    </p>

    <h3>validator</h3>
    <p>
      Профиль <strong>validator</strong> — однопроходный очиститель контактов. Он берёт существующий список
      контактов, верифицирует каждую запись и обогащает чем может. Запрещает <code>spawn_agent</code>, поэтому
      работает как сфокусированный однопроцессный агент.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">validator.toml</span></div>
      <pre><code set:html={`[profile]
name = "validator"
description = "Verify and enrich existing contacts"
prompt = """
You are a contact validation agent. You have been given an existing
contact list. For each contact: verify the email (syntax + MX + SMTP),
normalize the phone to E.164, check the social profile URL, and enrich
with any missing fields (title, company, LinkedIn). Mark invalid entries
but do not delete them. Return a clean, enriched list.
"""
temperature = 0.2
max_agents = 1
max_depth = 1
max_iterations = 50
deny_tools = ["spawn_agent"]`} /></pre>
    </div>
    <div class="code-card code-card--gap">
      <div class="code-header"><span class="code-lang">пример</span></div>
      <pre><code set:html={`fathom run --profile validator "Validate and enrich contacts in ./contacts.csv"`} /></pre>
    </div>
    <p>
      Что меняется: субагенты не запускаются — вся валидация идёт в одном цикле агента.
      <code>max_iterations = 50</code> даёт агенту запас для проверки больших списков без упора в лимит.
      Температура самая низкая из всех профилей (0.2) — для детерминированной механической работы.
    </p>
  </section>

  <section id="profile-inheritance">
    <h2>Наследование и разрешение профилей</h2>
    <p>
      Когда профиль не задаёт поле, рантайм разрешает его из <code>config.toml</code>. Порядок
      разрешения: TOML профиля → секция <code>[agent]</code> → встроенные значения по умолчанию.
      Минимальному профилю достаточно только <code>prompt</code> — всё остальное работает из коробки.
    </p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Приоритет</th><th>Источник</th><th>Пример</th></tr></thead>
        <tbody>
          <tr><td>1 — Профиль</td><td>TOML-файл профиля</td><td><code>temperature = 0.3</code> в analyst.toml</td></tr>
          <tr><td>2 — Конфиг</td><td><code>~/.fathom/config.toml</code></td><td><code>[agent] temperature = 0.7</code></td></tr>
          <tr><td>3 — Встроенные</td><td>Скомпилированные значения</td><td><code>temperature = 0.7</code></td></tr>
        </tbody>
      </table>
    </div>
    <p>
      Поле <code>prompt</code> <em>добавляется</em> к базовому системному промпту, а не заменяет его. То есть
      промпт профиля добавляет ролевые инструкции поверх стандартных правил безопасности, опоры на факты
      и использования инструментов, которые получает каждый агент.
    </p>
  </section>

  <section id="grounding-detail">
    <h2>Правила опоры на факты подробно</h2>
    <p>
      Четыре правила опоры на факты — разница между спамом и сигналом. У каждого правила есть конкретный
      пример «до/после», показывающий, как оно преображает черновик.
    </p>

    <h3>Правило A — Опора на факты</h3>
    <p>
      Автор использует только то, что реально вернули инструменты. Если веб-поиск нашёл анонс раунда B
      и вакансию на 6 инженеров, в черновик идут эти факты — и только они. Каждое утверждение
      отслеживается до URL источника.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">до (без опоры)</span></div>
      <pre><code set:html={`Здравствуйте, Анна! Заметил, что ваша компания быстро растёт и,
вероятно, ищет решения для масштабирования инфраструктуры.`} /></pre>
    </div>
    <div class="code-card code-card--gap">

    </div>

    <h3>Правило B — Никаких выдумок</h3>
    <p>
      Железное правило: никаких выдуманных фактов, контактов, дат или источников. Если факта нет,
      черновик либо прямо об этом говорит, либо начинается с того, что известно. Модель штрафуется
      в системном промпте за галлюцинации — выдумки вызывают немедленный перезапуск генерации.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">до (выдумано)</span></div>
      <pre><code set:html={`Здравствуйте, Анна! Поздравляю с недавним раундом B на $50M под
руководством Sequoia! Видел ваш недавний доклад на RustConf 2025
про микросервисы.`} /></pre>
    </div>
    <div class="code-card code-card--gap">
      <div class="code-header"><span class="code-lang">после (честно)</span></div>

ваших недавних наймов в инженерию говорит о серьёзном росте впереди.`} /></pre>
    </div>

    <h3>Правило C — Слой памяти</h3>
    <p>
      На глубине 0 агент получает <strong>дайджест памяти</strong> — компактную сводку всех прошлых
      взаимодействий с этим контактом или компанией. Прошлые касания, предыдущие разговоры и известные
      смены ролей всплывают автоматически, поэтому повторный аутрич продолжает диалог, а не начинает с нуля.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">до (без памяти)</span></div>
      <pre><code set:html={`Здравствуйте, Анна! Хотел представить нашу платформу и узнать,
есть ли совпадение интересов.`} /></pre>
    </div>
    <div class="code-card code-card--gap">
      <div class="code-header"><span class="code-lang">после (с учётом памяти)</span></div>
      <pre><code set:html={`Здравствуйте, Анна! Продолжаю наш разговор от января — вы упоминали,
что миграция на Rust была вашим приоритетом на Q1. Сейчас Q2, и я заметил,
что Acme нанимает инженеров платформы — похоже, всё получилось.
Интересно, как прошло развёртывание и пригодятся ли ещё наши бенчмарки.`} /></pre>
    </div>
    <p>
      Дайджест памяти включает: имя контакта, компанию, известную роль (и смены ролей), дату последнего
      взаимодействия, ранее обсуждавшиеся темы и любые факты из прошлых запусков. Эти данные внедряются
      как замороженный блок промпта на глубине 0, чтобы префикс-кэш оставался тёплым.
    </p>

    <h3>Правило D — Подтверждение человеком</h3>
    <p>
      Побочные эффекты ждут явного «да». Агент составляет черновик и останавливается. В TUI оператор нажимает
      <code>y</code> для подтверждения или <code>n</code> для отклонения. По API требуется вызов
      <code>POST /sessions/:id/approve</code>. Ничего не уходит в CRM, письма не отправляются, файлы не
      меняются, пока человек не скажет «го».
    </p>
    <p>
      Это значит, что можно запустить <code>--profile hunter</code> для генерации 50 персонализированных
      писем, просмотреть каждое в пакете и подтвердить только те, что проходят вашу планку качества.
    </p>
  </section>

  <section id="role-routing">
    <h2>Маршрутизация моделей по ролям</h2>
    <p>
      Таблица <code>[agent].role_models</code> в <code>config.toml</code> позволяет назначать разные LLM
      разным ролям агентов. Это главный рычаг оптимизации стоимости: дорогие модели там, где важно
      качество текста, и дешёвые везде в остальных местах.
    </p>
    <div class="code-card">
      <div class="code-header"><span class="code-lang">config.toml</span></div>
      <pre><code set:html={`[agent]
# Модель по умолчанию для всех ролей
model = "gpt-4o-mini"

# Переопределения конкретных ролей
[agent.role_models]
writer = "gpt-4o"            # лучшее качество текста
researcher = "deepseek-v3"   # дешёвая, хороша в извлечении
analyst = "claude-3.5-sonnet" # сильное рассуждение
verifier = "gpt-4o-mini"     # простые проверки, экономим
coordinator = "gpt-4o"       # планированию нужна сильная модель

[llm]
fast_model = "gpt-4o-mini"   # массовое извлечение и парсинг`} /></pre>
    </div>

    <h3>Как работает role_models</h3>
    <p>
      Когда координатор запускает субагента, он назначает роль по типу подзадачи. Рантайм сначала смотрит
      <code>[agent.role_models]</code>; если для роли задана модель, используется она.
      Иначе применяется <code>[agent].model</code>.
    </p>
    <div class="mini-table-wrap">
      <table class="mini-table">
        <thead><tr><th>Роль</th><th>Задачи</th><th>Рекомендуемый уровень модели</th></tr></thead>
        <tbody>
          <tr><td><code>coordinator</code></td><td>Планирование, декомпозиция, синтез</td><td>Сильное рассуждение (GPT-4o, Claude Sonnet)</td></tr>
          <tr><td><code>researcher</code></td><td>Веб-поиск, парсинг страниц, OSINT</td><td>Дешёвая + быстрая (DeepSeek, GPT-4o-mini)</td></tr>
          <tr><td><code>analyst</code></td><td>Перекрёстная проверка, фактчекинг</td><td>Сильное рассуждение (Claude Sonnet, GPT-4o)</td></tr>
          <tr><td><code>writer</code></td><td>Персонализированные черновики аутрича</td><td>Лучший текст (GPT-4o, Claude Opus)</td></tr>
          <tr><td><code>verifier</code></td><td>Проверка email/телефона/соцсетей</td><td>Дешёвая (GPT-4o-mini, локальные модели)</td></tr>
        </tbody>
      </table>
    </div>

    <h3>fast_model для массового извлечения</h3>
    <p>
      Настройка <code>llm.fast_model</code> используется для задач, где скорость важнее качества: парсинг
      HTML, извлечение структурированного JSON из страниц, классификация типов страниц, нормализация данных.
      Такие вызовы происходят сотни раз за сессию, поэтому более дешёвая OpenAI-совместимая модель заметно
      экономит бюджет без влияния на качество результата.
    </p>

    <h3>Стратегии оптимизации стоимости</h3>
    <div class="check-list">
      <div class="check-item"><span class="check-mark">✓</span><span>Используйте <code>fast_model</code> для всего извлечения и парсинга — это самый большой выигрыш</span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Держите координатора на сильной модели — плохое планирование тратит больше, чем экономит</span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Используйте сильную модель для автора — качество текста и есть результат</span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Используйте дешёвую модель для верификации — это в основном regex и DNS-запросы</span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Ставьте <code>temperature = 0.2</code> для задач извлечения, чтобы уменьшить перегенерации</span></div>
      <div class="check-item"><span class="check-mark">✓</span><span>Используйте лимиты <code>max_iterations</code> против бесконечных циклов на дешёвых моделях</span></div>

    <p>

      его, либо использует осторожную формулировку («не удалось проверить…»). Рантайм также проверяет,
