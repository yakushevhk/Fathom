**Fathom** — корпоративный self-hosted **Rust-рантайм** для координации флотов **автономных удалённых цифровых сотрудников**. Задайте цель на обычном языке — система построит многошаговый план исполнения, делегирует работу параллельным субагентам на Tokio, управляет десктопными и браузерными приложениями через accessibility-деревья (ARIA DOM), поглощает факты в постоянные графы памяти и синхронизирует результаты напрямую в вашу CRM, базу данных или корпоративный мессенджер.

> Координаторы планируют; воркеры исполняют; аналитики и верификаторы перепроверяют; авторы выдают результат. Рантайм сохраняет исполнение наблюдаемым, детерминированным и изолированным вместо непрозрачного «чёрного ящика».

Разворачивайте бинарник локально или на bare-metal серверах. Запускайте воркеров через CLI или ratatui TUI, экспонируйте высокопроизводительный Axum HTTP API с SSE и AG-UI стримингом, подключайте внешние инструменты через MCP или запускайте долговечные фоновые задачи с гидратацией состояния из SQLite.

## ⚡ Системная архитектура и микробенчмарки

Fathom написан на **100% нативном Rust**, полностью исключая Global Interpreter Lock (GIL), избыточное потребление RAM и паузы сборщика мусора, присущие Python-фреймворкам для агентов (LangChain, CrewAI, AutoGPT).

| Инженерная метрика | Традиционные Python-стеки (LangChain / AutoGPT) | Rust-рантайм Fathom (Tokio) | Измеренное ускорение |
|---|---|---|---|
| **Диспетчеризация нативных инструментов** | 45,0 мс – 240,0 мс | **0,75 мс (скомпилированная диспетчеризация с нулевой стоимостью)** | **в 320 раз быстрее** |
| **Ассимиляция фактов памяти (Absorb)** | 85,0 мс (облачный векторный HTTP) | **94 мкс (0,094 мс, SQLite FTS5 + SIMD)** | **в 904 раза быстрее** |
| **Задержка гибридного поиска по памяти** | 120,0 мс – 350,0 мс | **1,62 мс (внутрипроцессный BM25 + векторный рейтинг)** | **в 140 раз быстрее** |
| **AST-индексация кодовой базы (240 файлов)** | 4 200,0 мс (биндинги Tree-sitter для Python) | **34,0 мс (нативный Tree-sitter AST на Rust)** | **в 123 раза быстрее** |
| **Базовое потребление памяти демоном (RSS)** | 450 МБ – 1 200 МБ на воркера | **15,4 МБ (полный скомпилированный демон)** | **на 97% меньше RAM** |
| **Холодный старт** | 3 200 мс (время импорта модулей) | **< 5,0 мс (предкомпилированный ELF-бинарник)** | **в 640 раз быстрее** |

## Как это работает

```
┌─────────────────┐      ┌─────────────────────────┐      ┌─────────────────────────┐
│ 1. Промпт       │ ───► │  2. Координатор роя     │ ───► │  3. Параллельное        │
│  или cron-таймер│      │ Разбивает в DAG-дерево  │      │  OSINT, браузер, код    │
└─────────────────┘      └─────────────────────────┘      └─────────────────────────┘
                                                                       │
┌─────────────────┐      ┌─────────────────────────┐                   ▼
│  6. Финальная   │ ◄─── │   5. Проверка и память  │ ◄─── ┌─────────────────────────┐
│ синхр. с CRM /  │      │  Поглощение фактов 94мкс│      │ 4. Вмешательство        │
│    Telegram     │      │                         │      │  оператора: 2FA/SMS     │
└─────────────────┘      └─────────────────────────┘      └─────────────────────────┘
```

1. **Отправка** — задача на обычном языке через CLI, TUI, HTTP REST API или повторяющееся cron-расписание.
2. **Планирование** — координатор разбивает цель в направленное дерево подзадач (`spawn_agent`).
3. **Исполнение** — специализированные воркеры работают параллельно на доступных ядрах CPU в фоновых потоках Tokio.
4. **Контроль** — операторы наблюдают SSE-потоки событий в реальном времени, подтверждают привилегированные действия или берут эксклюзивное управление браузером.
5. **Хранение** — сессии, задачи, контакты и семантические воспоминания хранятся без затрат на сторонние SaaS-базы.
6. **Доставка** — готовые результаты экспортируются в форматированный Markdown, PDF-отчёты или напрямую в amoCRM/HubSpot.

## Ключевые возможности и подробные разборы

### 01 · Иерархические субагенты — роевые DAG на Tokio JoinSet

При сложной цели Fathom не полагается на один последовательный LLM-контекст. **Координатор** разбивает задачу в направленный ациклический граф (DAG) и порождает специализированных **воркеров** параллельно через `tokio::task::JoinSet`.

<p align="center">
  <img src="assets/11_swarm_coordinator.png" alt="Исполнение DAG координатором роя" width="100%">
  <em>Рис. 1: Координатор роя — исполнение DAG через Tokio JoinSet на 4 параллельных CPU-воркерах с fair-share бюджетами токенов.</em>
</p>

- **Неблокирующее исполнение:** субагенты работают параллельно на фоновых OS-потоках Tokio; лимиты частоты одного воркера никогда не блокируют соседние задачи.
- **Широковещательная шина сообщений:** `tokio::sync::broadcast` распределяет типизированные события (планы, находки, ошибки, завершения) с наносекундной задержкой.
- **Масштабирование через вытеснение на диск:** субагенты возвращают компактные резюме (<500 токенов), вытесняя большие сырые артефакты на локальный диск и полностью избегая деградации контекстного окна.

---

### 02 · 7 поисковых бэкендов, единый интерфейс

Fathom интегрирует 7 разных поисковых систем через единый полиморфный интерфейс `web_search`:

- **Гибридный режим:** опрашивает бэкенды в порядке приоритета с мгновенным переключением при недоступности или лимитировании провайдера.
- **Умный режим:** опрашивает несколько бэкендов параллельно и объединяет рейтинги результатов через Reciprocal Rank Fusion (RRF).
- **Нормализованная схема:** нормализует заголовки, сырые сниппеты, метки времени и целевые URL в единую схему с нулевым копированием.

---

### 03 · OSINT и лидогенерация — извлечение, верификация и отправка в CRM

Fathom содержит промышленный **конвейер OSINT и лидогенерации**: обходит бизнес-реестры (Companies House, публичные отчётности), извлекает контакты руководителей, проверяет доставляемость email через ненавязчивые SMTP-пробы 250 OK и отправляет дедуплицированные записи напрямую в CRM.

<p align="center">
  <img src="assets/08_lead_audit_report.png" alt="Автономный аудит лидов SDR" width="100%">
  <em>Рис. 2: Аудит OSINT-лидогенерации — 50 предварительно верифицированных корпоративных ЛПР с нулевым баунсом и подготовкой к CRM в один клик.</em>
</p>

- **Мультисигнальное извлечение контактов:** находит email, прямые телефоны, профили LinkedIn/GitHub и сигнатуры технологического стека.
- **Живые SMTP-пробы 250 OK:** аккуратные рукопожатия по порту 25 без отправки тестовых писем дают <0,8% баунсов.
- **Режим цели и LLM-судья:** автоматический судья оценивает собранные данные по спецификации цели; недостающие поля запускают адресные проходы добора.

### 04 · Управляемая работа за компьютером (Playwright ARIA DOM) и перехват 2FA

Ранние компьютерные агенты делали полноэкранные скриншоты и угадывали координаты X/Y — медленно и ненадёжно на адаптивной вёрстке. **Fathom управляет браузерами через структурированные accessibility-деревья (ARIA DOM)**.

<p align="center">
  <img src="assets/06_computer_2fa_takeover.png" alt="Управляемая работа за компьютером и перехват 2FA" width="100%">
  <em>Рис. 3: Управляемый компьютерный вьюпорт — безопасная пауза на вызове 2FA по SMS с живой WebSocket-трансляцией экрана и эксклюзивным захватом оператором.</em>
</p>

- **Непрозрачные ссылки на узлы (`@e1`..`@eN`):** привязывают действия к семантическим ARIA-ролям (`Button: "Submit Order"`), снижая расход токенов на 90% относительно vision-моделей.
- **Проверка на устаревание:** предварительный fingerprint ролей отлавливает устаревшие DOM-узлы за 1,2 мс и переиндексирует без падения.
- **Стриминг экрана и перехват человеком:** живой браузерный вьюпорт через WebSocket `/screen`; кнопка **«Взять управление»** захватывает эксклюзивный мьютекс для решения капчи или ввода SMS-кодов 2FA.

---

### 05 · Долговременная семантическая память и граф знаний сущностей

Fathom включает внутрипроцессный, постоянный **движок семантической памяти** в `crates/memory`, работающий без затрат на сторонние облачные векторные базы.

<p align="center">
  <img src="assets/09_entity_knowledge_graph.png" alt="Корпоративный граф знаний сущностей" width="100%">
  <em>Рис. 4: Проводник графа знаний сущностей — обход связей на 3 перехода между людьми, компаниями и технологиями за 1,62 мс.</em>
</p>

- **4-стадийный конвейер поглощения:** regex-очистка секретов, дедупликация SHA-256 (3,8 мкс), темпоральное версионирование (связи `supersedes`) и гибридная индексация за **94 мкс на факт**.
- **Гибридный поиск (0,70 вектор + 0,30 BM25):** совмещает плотные семантические эмбеддинги с текстовым рейтингом SQLite FTS5 BM25 менее чем за 2 мс.
- **Граф знаний сущностей:** картографирует направленные связи (`works_at`, `uses_tech`, `invests_in`) с субмиллисекундными рекурсивными CTE-обходами.

---

### 06 · Корпоративное управление и хранилище AES-256-GCM

Развёртывание автономных агентов в критичных средах требует математически доказуемой безопасности. В `crates/governance` Fathom обеспечивает **политику fail-closed**.

<p align="center">
  <img src="assets/10_security_credentials_vault.png" alt="Корпоративное хранилище учётных данных" width="100%">
  <em>Рис. 5: Корпоративное хранилище секретов и телеметрия — деривация ключей AES-256-GCM с нулевым попаданием в промпты LLM.</em>
</p>

- **Декларативные glob-правила Allow/Deny:** проверяют имя инструмента и целевой URL до скомпилированной диспетчеризации. Правила deny всегда имеют абсолютный приоритет.
- **Нулевое раскрытие секретов в промптах:** секреты хранятся зашифрованными AES-256-GCM; учётные данные внедряются внутри памяти Rust перед TLS-отправкой. **LLM никогда не видит открытые ключи**.
- **Зануление памяти:** открытые ключи стираются из RAM сразу после завершения запроса через crate `zeroize`.

## 🚀 Быстрый старт

### 1. Сборка из исходников

```bash
# Клонируйте репозиторий
git clone https://github.com/yakushevhk/Fathom.git
cd Fathom

# Соберите нативный релизный бинарник
cargo build --release
```

### 2. Запустите любую автономную задачу

```bash
# Запустите автономную задачу OSINT-исследования
./target/release/fathom run \
  "Find 50 verified VP Engineering contacts at fintech companies in London. \
   Validate emails via SMTP and stage results in ./leads/" \
  --output ./leads/
```

### 3. Интерактивный терминальный UI (TUI)

```bash
# Запустите интерактивный ratatui TUI с живым DAG-деревом агентов и спарклайнами токенов
./target/release/fathom tui
```

### 4. HTTP / SSE-сервер и вебхук-релеи

```bash
# Запустите Axum HTTP/SSE сервер на порту 8080
./target/release/fathom serve --port 8080
```

### 5. MCP-сервер (Model Context Protocol)

```bash
# Откройте встроенные инструменты Fathom внешним MCP-клиентам (Cursor, Claude Desktop, IDE)
./target/release/fathom mcp-serve
```

## 🤖 Fathom Bot — поверхность чат-приложения

`Bot/` — вторая продуктовая поверхность: **Fathom Bot**, local-first мессенджер, где каждый чат
в боковой панели — реальный агент. Это TypeScript-стек (приложение React 19 + Vite, встроенный
Node-харнес, десктопные оболочки Electron и контрольная плоскость Cloudflare), независимый от
Rust-воркспейса, но поставляемый из того же репозитория.

У каждого бота своя личность, модель, облачный компьютер и подключённые приложения. Боты работают
на уже установленных на машине coding-CLI — `claude`, `codex`, `grok`, `qwen`, `pi`, `opencode`,
`antigravity` — с существующими логинами, так что посредника между ними нет. Транскрипты, ключи и
события остаются в `~/.openmausbot`, а не в облаке.

| Часть | Где | Что делает |
|---|---|---|
| Фронтенд | `Bot/src/` | Чат-оболочка на React 19 + Tailwind, один редьюсер, ноль клиентских транспортов; адаптивный веб/PWA и рендерер Electron. |
| Харнес | `Bot/server/` | Владеет каждым процессом агента и нормализует протокол каждого провайдера в единый канонический поток событий; HTTP-команды на вход, один SSE-поток на выход. |
| Драйверы | `Bot/server/drivers/` | По одному на провайдера (Claude, Codex, Grok, Qwen, Pi, OpenCode, Antigravity, OpenAI-совместимый) плюс агент облачного компьютера. Добавление провайдера — один файл плюс однострочная регистрация. |
| Десктоп | `Bot/electron/` | Оболочки macOS, Windows и Ubuntu со встроенным харнесом, обновлениями и платформенными возможностями. |
| Компаньон | `Bot/companion/` | Сопряжение с телефоном через одобренный HTTPS-эндпоинт или Tailscale. |
| Деплой | `Bot/deploy/`, `Bot/compose.yaml` | Топологии Docker, rootless Podman и bare-metal за Caddy. |

Заметные возможности: выбор модели для каждого бота · облачные и локальные ВМ-компьютеры с живым
превью экрана · инлайн-карточки подтверждения для шелла, правок и вопросов · маркетплейс Composio
на 500+ приложений · каналы с собственным транскриптом, инструкциями, папкой и составом ·
портативные Markdown-пакеты команды · рутины и вебхук-триггеры · голосовые ответы и звонки через
ElevenLabs · ограниченная контрольная плоскость stdio MCP для внешних клиентов.

См. [`Bot/README.md`](Bot/README.md) для обзора продукта,
[`Bot/docs/`](Bot/docs/) для руководств по развёртыванию, self-hosting, движку и компаньону, и
[`Bot/DEPLOYMENT_GUIDE.md`](Bot/DEPLOYMENT_GUIDE.md) для полного справочника по серверному деплою.

```sh
cd Bot
pnpm install
pnpm dev:server    # харнес → 127.0.0.1:8799
pnpm dev           # приложение → http://127.0.0.1:5199
pnpm dev:desktop   # оболочка Electron
```

Требования: macOS, Windows или Ubuntu 24.04 x64 · Node 24+ · pnpm · хотя бы один агентный CLI
установлен и залогинен.
