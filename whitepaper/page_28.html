Real-Time Communication & Bank-Grade Security Architecture

Enterprise operations require both instant real-time visibility and zero-compromise credential security. Fathom implements an in-memory broadcast message bus coupled with an AES-256-GCM hardware security vault.

Figure 28.1: Enterprise Security Vault & Telemetry — AES-256-GCM hardware key derivation with zero LLM prompt exposure
1. Broadcast Message Bus & SSE Relays
  • Lock-Free Broadcast: tokio::sync::broadcast distributes state events to all connected clients.
  • Server-Sent Events: Streams token-by-token thought processes and live tool outputs to Web, Slack, and Telegram.
  • Reactive Wakeup: Workers sleep with zero CPU usage until an incoming event triggers execution.
2. AES-256-GCM Credential Vault (Ring)
  • Hardware Encryption: All stored CRM keys and passwords are encrypted at rest using AES-256-GCM.
  • Zero Prompt Exposure: Secrets are resolved in Rust memory before TLS dispatch; LLMs never see keys.
  • Memory Zeroization: Plaintext keys are wiped from RAM immediately after HTTP dispatch.
Enterprise Security Standard: Security officers can configure enterprise CRM integrations with complete confidence that keys remain cryptographically locked and completely invisible to LLMs.
